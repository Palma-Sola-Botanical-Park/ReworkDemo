# ReworkDemo — Palma Sola Botanical Park website

Static site for Palma Sola Botanical Park (PSBP), hosted on **GitHub Pages**.
Intended to eventually replace the WordPress site at `palmasolabp.org`.

- **Live URL:** https://palma-sola-botanical-park.github.io/ReworkDemo/
- **Local clone:** `/Users/fiona/Documents/GitHub/ReworkDemo/`
- **Deploy:** commit + push via GitHub Desktop. GitHub Pages rebuilds automatically (allow a few minutes of lag).

This is a plain HTML/CSS/JS site — no build step, no framework. Every file is served as-is.

---

## How the site is wired

### Shared shell (the thing that makes every page consistent)
`js/site.js` is the brain. Every page is a thin HTML file that:
1. links `css/site.css`,
2. has empty `<div id="nav-placeholder">` and `<div id="footer-placeholder">` divs,
3. loads `js/site.js`,
4. calls `injectShared({ ... })`.

`injectShared()` injects the shared nav and footer into those placeholders, so the
nav/footer are defined **once** in `site.js` and appear on every page. Change them there,
not per-page.

Options passed to `injectShared()`:
- `inatBar: true` — builds the live iNaturalist stats bar into `#inat-bar-placeholder`
- `inatFooter: true` — injects iNaturalist stats into the footer
- (omit/false = neither). If you set `inatBar`/`inatFooter`, also call `loadINat()` to fill it.

### The link router (`viewer.html`)
`site.js` has a link router (`PSBP.linkKind` / `linkTag`) that decides how every
content link behaves, based on the URL:
- internal page → same window
- external site → new tab
- **PDF or published Google Doc → framed inside `viewer.html`** (in-site, with a Back button)
- `mailto:` / `tel:` → native

`viewer.html` is **not a nav page** — it's a shared subroutine the router points at.
Do not delete it.

## Data layer

The site reads from two sources: **static JSON files** (baked from HTML pages) and
**live Google Sheets** (read at page load).

### Static JSON (committed to the repo)
| File | What it is | Generated by |
|------|-----------|--------------|
| `plants.json` | Flattened summary of all plant pages (~122) — feeds Plants tab search/filter | `data/scripts/generate_plants_json.py` |
| `wildlife.json` | Same, for wildlife pages (~30) | `data/scripts/generate_wildlife_json.py` |
| `photo_focus.json` | Per-image crop focal points (filename → object-position) | written by `photo-focus.html` picker; baked into pages by `apply_photo_focus.py` |

These three live in the **repo root** and are read directly by the site. Don't move them.

### Live Google Sheets (read at page load)
`events`, `classes`, `announcements`, `volunteer`, `newsletters`, and `news` are pulled
live from one Google Sheet via `fetchTab(gid)` in `site.js`. Each tab is fetched as CSV:
`https://docs.google.com/spreadsheets/d/<SHEET_ID>/export?format=csv&gid=<GID>`

The sheet must be shared as **"Anyone with the link → Viewer"** or the fetch fails.

> **Note:** these live tabs currently have **no repo fallback** — if Google is slow/down,
> those tabs come up empty. (Future hardening: nightly bake each tab to JSON so they
> have a floor, same pattern as plants/wildlife.)

| `data/scripts/` | Generators & tools (`generate_*_json.py`, `apply_photo_focus.py`, etc.) | **All scripts live here — never in asset/page folders** |

### Naming conventions
- **PSBP IDs:** plants `PSBP-00001`–`00122+`; wildlife `PSBP-99970`–`99999`.
- A species has a page (`plants/` or `wildlife/`) **and** a photo (`photos/`) sharing the same ID.
- Plants missing a real photo use a copy of `photos/PLACEHOLDER-plant-green.jpg`.

## Common tasks

**Regenerate plant data after editing/adding plant pages:**
```bash
cd /Users/fiona/Documents/GitHub/ReworkDemo
python3 data/scripts/generate_plants_json.py
```
(same idea for `generate_wildlife_json.py`). Then commit + push.

**Re-bake photo focal points** after re-running the `photo-focus.html` picker:
```bash
python3 data/scripts/apply_photo_focus.py
```
This reads `photo_focus.json` and writes `object-position` into the wildlife pages.
Editing the JSON alone changes nothing until this runs.

**Add an event / newsletter / announcement (content, not code):**
Edit the Google Sheet tab (see Content Backend above). Changes appear live on next load —
no deploy needed. Each row's `display` column (`both` / `web` / `screen` / `off`) controls
where it shows.
